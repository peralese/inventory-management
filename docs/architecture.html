Factory Inventory Management System

Architecture overview: a Vue 3 single-page app backed by a FastAPI service that serves in-memory data loaded from JSON files. No database.

System architecture

Tech stack

Frontend

  • Vue 3, Composition API
  • Vue Router 4 (history mode)
  • Axios for HTTP
  • Vite 8 dev server and build
  • Custom SVG charts, CSS Grid
  • English and Japanese locales

Backend

  • Python 3.11+, FastAPI
  • Uvicorn ASGI server
  • Pydantic 2 response models
  • In-memory lists, no database
  • Dependencies managed with uv

Tooling and tests

  • pytest, pytest-asyncio, httpx
  • FastAPI TestClient (tests/backend)
  • Playwright MCP for browser checks
  • GitHub MCP for repo operations
  • Claude Code agents and skills in .claude/

Data flow

  1. Filter state changes Four shared filters (period, location, category, status) live as module-level refs in useFilters.js, so every view reads the same state.
  2. View reloads data Views watch the filter refs and call loadData(), which passes getCurrentFilters() to the API client. "all" values are dropped from the query string.
  3. Axios request api.js issues a GET to http://localhost:8001/api/... with query params. CORS allows all origins.
  4. FastAPI filters in memory The route runs apply_filters (warehouse, category, status) and filter_by_month (month or quarter, matched against order_date) over lists loaded by mock_data.py.
  5. Pydantic validates the response Routes with a response_model are serialised through the models. Changing a JSON shape requires updating the matching model.
  6. Refs hold raw data, computed derives views Raw responses go into refs such as allOrders and inventoryItems. KPIs, chart series and top-product tables are computed properties over them.

Project layout

client/

  • src/main.js: app bootstrap and route table
  • src/views/: Dashboard, Inventory, Orders, Demand, Spending, Reports (plus an unrouted Backlog view)
  • src/components/: filter bar, detail modals, profile and language menus
  • src/composables/: shared filters, i18n, auth state
  • src/api.js: all HTTP calls

server/ and tests/

  • server/main.py: app, models, routes, filter helpers
  • server/mock_data.py: JSON loader
  • server/generate_data.py: regenerates sample data
  • server/data/*.json: the data store
  • tests/backend/: dashboard, inventory and misc endpoint tests

Known gaps

  • The data store is read-only at runtime. Nothing writes back to the JSON files, and purchase_orders.json is an empty list.
  • api.js calls /api/tasks and POST /api/purchase-orders, but main.py defines neither, so the tasks list and purchase-order creation return 404.
  • Dashboard.vue renders PurchaseOrderModal, but no such component exists in client/src/components/.
  • Reports.vue calls axios directly against /api/reports/* instead of going through api.js, and Backlog.vue is not registered in the router.
  • The API base URL is hard-coded in api.js (and again in Reports.vue), and CORS allows every origin. Both are fine for a local demo only.
